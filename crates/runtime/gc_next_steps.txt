Remaining gaps after finishing v1 of garbage collection

1. Descriptors

Uses `leak` to have a static lifetime, since the code might outlive `JIT`.
If we want to reclaim the descriptors themselves we'll need to think about JIT code registration cycle (unregistering and coordinating the descriptor lifetimes)

2. Heap allocator

Non-compacting and there's no mitigation for fragmentation. Uses the system allocator per object, no specialized allocator or group allocation. No free-list allocator.

3. Roots

No validation for dereferencing root words, a stale/corrupted raw pointer could cause unsafe memory access

4. Concurrency and Platform

Makes several assumptions around ABI. Windows and architectures besides Mac ARM64 and Linux x86-64 are unsupported.
Effectively single-threaded execution "Stop the world"

5. Native interop

Still specific entry points, no generic return bridge for aggregates

6. Not implemented types

Arrays and closures are the main ones. There's some nested union layouts that are rejected by the compiler that should eventually be allowed.

7. Testing

Don't have long-running fragmentation tests, release mode stress tests (forced collection requires debug profile currently), and no performance benchmarks
